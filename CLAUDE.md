# Polski Kurwa — тренажёр польского языка

Учебный проект: интерактивные тесты по польскому для самостоятельного изучения (A1 → выше).
Интерфейс и объяснения — **на русском**, материал — на польском.
Живёт на GitHub Pages, ставится на iPhone как приложение.

> Этот файл — рабочая память проекта. Читай его перед каждой задачей и **обновляй**,
> когда меняется структура, добавляется тема или принимается новое решение.

---

## 1. Файлы

Репозиторий = сайт. Всё в корне публикуется как есть.

| Файл | Что это |
|---|---|
| `index.html` | **Всё приложение целиком**: разметка, стили, движок и данные всех тем. Без сборки, без зависимостей. |
| `manifest.webmanifest` | PWA-манифест: имя, иконки, `display: standalone`, цвета. |
| `sw.js` | Service worker. **Сеть первым делом, кэш как запасной вариант** — онлайн всегда свежая версия, офлайн последняя загруженная. Версию бампать не надо. |
| `icons/` | `icon.svg` — исходник (серифная «ę» на терракоте), PNG генерятся из него через `sips` (§7). |
| `deploy.sh` | Публикация одной командой. |
| `.nojekyll` | Отключает Jekyll на GitHub Pages. |
| `CLAUDE.md` | Этот файл. |

**Версионирование — через git**, не через имена файлов.

**Все темы живут в одном `index.html`** — движок общий, дублировать его по файлам нельзя.
(Раньше в этом файле стоял план разносить темы по отдельным HTML — от него отказались:
это означало бы копировать ~700 строк движка на каждую тему.)

## 2. Архитектура

```
<head>                    мета + PWA-теги + запрет зума
<style>                   :root палитра, экраны, карточки, модал
<body>                    «скелет»: header (#headerBadge/#headerTitle/#headerSub),
                          #app (сюда рисуется всё), #footerNote, модал
<script>
  ОБЩЕЕ                   shuffle(), normalize()
  ТЕМА: ГЛАГОЛЫ           PERSON_*, PARADIGMS, EXCEPTIONS, CONJ_GROUPS, VERB_DATA
  ТЕМА: ЧИСЛИТЕЛЬНЫЕ      NUM_SUBTOPICS, NUM_REF, NUM_DATA
  РЕЕСТР ТЕМ              TOPICS = {czasowniki, liczebniki}, TOPIC_ORDER
  ДВИЖОК                  состояние → renderHome / renderSetup / renderQuiz
                          / checkAnswers / renderSummary / модал
```

### Четыре экрана

`home` (выбор темы) → `setup` (подтемы + сколько тестов) → `quiz` → `summary`.
Переключает `state` + `render()`.

### Контракт темы

Движок **ничего не знает** про глаголы и числительные. Он умеет работать с любой темой,
которая отдаёт вопросы в общем формате:

```js
{
  g:        'ключ группы',      // по нему считается статистика и строятся итоги
  hint:     'подпись',          // мелким шрифтом в шапке карточки
  sentence: 'Ona ___ miła.',    // ровно один пропуск ___
  answer:   'jest',
  alt:      ['вариант'],        // необязательно: другие допустимые ответы
  ref:      'ключ справки'      // что открыть в модале по клику
}
```

Сама тема в `TOPICS`:

```js
{
  id, title, subtitle, quizTitle,   // тексты
  mark: 'cz',                       // 1–2 знака в цветном квадрате на главной
  level: 'A1',
  subtopics: [{id,label,caption}] | null,   // null = экран настройки без чипов
  footer:   'что показать в подвале',
  hintNote: 'подсказка в шапке во время теста',
  blockInput: false,                // true = поле ввода под предложением на всю ширину

  questions(subs),                  // → массив вопросов; subs = Set выбранных подтем или null
  groupLabel(key),                  // → человекочитаемое имя группы для итогов
  wrongHtml(q),                     // → HTML фидбэка при ошибке
  adviceHtml(key),                  // → <li> совета «что подтянуть»
  reference(refKey)                 // → {title, tag, sub, cols, rows} для модала
}
```

`blockInput` нужен там, где ответ длинный (числительные): предложение показывает
пунктирный пропуск `.blank-gap`, а поле ввода уезжает под него на всю ширину карточки.
Ширина поля **не зависит от длины ответа** — иначе она подсказывала бы ответ.

### Как добавить тему

1. Блок данных в `<script>` рядом с остальными.
2. Объект в `TOPICS` по контракту выше.
3. `id` в `TOPIC_ORDER`.
4. Цвет плитки: `.topic-mark-<id>` в стилях.

Больше нигде править не нужно — главная, настройка, тест, итоги и модал соберутся сами.

## 3. Правила при изменениях

1. **Ноль зависимостей и ноль сборки.** Никаких CDN и npm. Любой внешний файл сломает офлайн и его придётся вносить в `ASSETS` в `sw.js`.
2. **Зум запрещён намеренно** — `user-scalable=no` в `<meta viewport>`, `touch-action:manipulation` в CSS (двойной тап) и `preventDefault` на `gesture*` (щипок в Safari). Не «чинить» это как баг.
3. **Инвариант глаголов:** `answer === PARADIGMS[v][PERSON_ORDER.indexOf(person)]`; каждый глагол либо в `EXCEPTIONS`, либо ровно в одной группе `CONJ_GROUPS`.
4. **Инвариант числительных:** `sub` есть в `NUM_SUBTOPICS`, для него есть таблица в `NUM_REF`, в предложении ровно один `___`.
5. После правки данных — прогнать проверку целостности (§5).
6. **Подтема должна тянуть на полный тест** — минимум 10 вопросов, иначе её нельзя выбрать одну.
7. **Стиль UI:** только переменные из `:root`, Georgia для контента / system-ui для интерфейса, скруглённые карточки. Мобильный — одна колонка (`max-width:600px`).
8. **Язык:** UI и объяснения по-русски, примеры по-польски, уровень A1.
9. **Иконки не редактировать вручную** — править `icons/icon.svg` и перегенерировать (§7).
10. После правок — `./deploy.sh "что изменил"`.

### Отдельно про содержание числительных

Числительные в польском управляют падежом существительного, поэтому **пропуск всегда только на само числительное**, а существительное уже стоит в предложении в правильной форме. При добавлении вопросов сверяй:

- 1 → единственное число: *jeden złoty*
- 2, 3, 4 и составные на них → именительный мн.: *dwadzieścia dwa **lata**, sześćdziesiąt cztery **osoby***
- 5–21 и всё остальное → родительный мн.: *dwadzieścia pięć **lat**, sto jeden **złotych***
- после 2/3/4 тысяч — *tysiące*, после 5+ — *tysięcy*

## 4. Текущее состояние контента

| Тема | Вопросов | Тестов | Разбито на |
|---|---|---|---|
| Глаголы | 122 | 12 | 5 групп спряжения + исключения, 29 глаголов |
| Числительные | 130 | 13 | 6 подтем |

**Глаголы.** Группы: A «I спряжение» (-ać, *czytać*), B «на -ować», C «II спряжение» (-ę/-esz, *pisać*), D «III спряжение» (-ę/-isz, *mówić*), E «тип на -mieć» (*rozumieć*), плюс `EXCEPTIONS`: być, mieć, iść, jechać, jeść, chcieć, móc, wiedzieć.

**Числительные.** Цифры 19 · Десятки 26 · Сотни 20 · Тысячи 18 · Даты 24 · Время 23.

### Известные шероховатости (не трогать без запроса)

- **Нумерация спряжений не польская.** В польской традиции I = `-ę/-esz` (*pisać*), II = `-ę/-isz` (*mówić*), III = `-am/-asz` (*czytać*). В проекте I и III местами. Переименование сломает привычку — только по явной просьбе.
- **`spać` в группе D** формально ок по окончаниям (śpię/śpisz), но чередование `a→ś` не объясняется.
- Покрытие глаголов по лицам неровное: `ja` 29, `ty` 29, `on/ona/ono` 26, `oni/one` 21, `my` 10, `wy` 7.
- Хвост вопросов после деления на десятки в сессию не попадает (122 % 10 = 2, 130 % 10 = 0).
- Диакритика сверяется строго: `mowie` ≠ `mówię`. Регистр и лишние пробелы прощаются.

## 5. Проверка целостности данных

После правки данных:

```bash
python3 - <<'EOF'
import io,re,subprocess
s=io.open('index.html',encoding='utf-8').read()
verbs=s[s.index('const PERSON_LABEL'):s.index('const NUM_SUBTOPICS')]
nums=s[s.index('const NUM_SUBTOPICS'):s.index('/* ============ РЕЕСТР ТЕМ')]
js=verbs+nums+'''
let bad=0;
const idx=p=>PERSON_ORDER.indexOf(p);
VERB_DATA.forEach((q,i)=>{
  const f=PARADIGMS[q.v];
  if(!f){console.log('нет парадигмы:',q.v);bad++;return;}
  if(f[idx(q.person)]!==q.answer){console.log(i,q.v,q.person,'ожидалось',f[idx(q.person)]);bad++;}
  if(!EXCEPTIONS.has(q.v)&&!Object.values(CONJ_GROUPS).some(G=>G.verbs.includes(q.v))){console.log('без группы:',q.v);bad++;}
});
const ids=new Set(NUM_SUBTOPICS.map(s=>s.id)), per={};
NUM_DATA.forEach((q,i)=>{
  per[q.sub]=(per[q.sub]||0)+1;
  if(!ids.has(q.sub)){console.log('чужая подтема:',i,q.sub);bad++;}
  if(!NUM_REF[q.sub]){console.log('нет справки:',q.sub);bad++;}
  if(q.sentence.split('___').length-1!==1){console.log('пропуск не один:',i);bad++;}
});
NUM_SUBTOPICS.forEach(s=>{if((per[s.id]||0)<10){console.log('меньше 10 вопросов:',s.id,per[s.id]||0);bad++;}});
console.log(bad?bad+' ПРОБЛЕМ':'OK — глаголы '+VERB_DATA.length+', числительные '+NUM_DATA.length);
'''
subprocess.run(['node','-e',js])
EOF
```

## 6. Куда расширять

- **Числительные:** порядковые (pierwszy/drugi…), «ile masz lat», цены с гроszami, номера телефонов, собирательные (dwoje, troje).
- **Глаголы:** добить `my`/`wy`, довести каждый глагол до 6 форм, добавить A1-глаголы (`wracać`, `dzwonić`, `oglądać`, `sprzątać`, `myć się`, `budzić się`, `nazywać się`, `wstawać`, `brać`, `dawać`).
- **Новые темы (каждая — объект в `TOPICS`):** прошедшее время, падежи (Biernik / Narzędnik / Miejscownik), множественное число, предлоги, притяжательные, вид глагола.
- **Механика:** режим повторения только ошибок, прогресс в `localStorage`, мягкая проверка диакритики с предупреждением, обратный перевод RU→PL, озвучка через Web Speech API.

## 7. iPhone: установка и обновление

**URL сайта:** https://elmishgan.github.io/polski/
**Репозиторий:** https://github.com/elmishgan/polski (публичный — бесплатный Pages иначе не работает)

### Разовая установка

1. Открыть URL в **Safari** (Chrome на iOS не умеет ставить на домашний экран).
2. «Поделиться» → **«На экран «Домой»»** → «Добавить».
3. Иконка «Polski». Полный экран, без адресной строки, работает офлайн, зум отключён.

### Обновление

```bash
./deploy.sh "что изменил"
```

Через ~30 секунд GitHub Pages пересобирается. На телефоне достаточно закрыть и снова
открыть иконку **при наличии сети**. Офлайн отдаётся последняя загруженная версия.

Если версия застряла: «Настройки → Safari → Очистить историю и данные» либо удалить
иконку и поставить заново.

### Локальная проверка

Service worker требует `https://` или `localhost` — с `file://` не зарегистрируется
(приложение откроется, но без офлайн-кэша).

```bash
python3 -m http.server 8765
```

### Перегенерация иконок

```bash
for s in 180 192 512; do sips -s format png -Z $s icons/icon.svg --out icons/icon-$s.png; done
sips -s format png -Z 512 icons/icon-maskable.svg --out icons/icon-maskable-512.png
```

`icon-maskable.svg` — та же «ę», но мельче: у maskable-иконок края обрезаются,
содержимое должно помещаться в центральные 80%.
